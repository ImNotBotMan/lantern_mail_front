# Друзья

## Responsibility

**Ответственность:** экран людей в браузере — список друзей, входящие и исходящие заявки,
поиск пользователей с их связью с текущим пользователем, действия заявок и удаление из друзей.

## Boundary

- Разрешено: `module-front-api-client` (`/users/search`, `/friends/*`), `module-front-session`,
  `module-front-i18n-ui`.
- Запрещено: вычислять статус связи на клиенте (его считает сервер), сопоставлять результаты
  поиска со списками друзей и заявок вручную, обращаться к сети напрямую.

## Экран `/friends`

Три части, все данные — из трёх запросов: `GET /friends`, `GET /friends/requests/incoming`,
`GET /friends/requests/outgoing`.

- **Друзья** — `username`, с какого момента (`friends_since`), действие «Удалить из друзей».
- **Заявки ко мне** — от кого и когда; действия «Принять», «Отклонить».
- **Мои заявки** — кому и когда; действие «Отозвать».
- Пустое состояние каждой части — отдельный текст, а не пустой блок.

## Поиск

- Поле ввода ищет по началу `username`; запрос уходит с задержкой после ввода (не на каждую
  букву) и только с 3 символов — короче сервер отвечает 422.
- Введённое приводится к нижнему регистру; разрешённые символы `[a-z0-9_]` — те же, что в
  регистрации.
- Для каждого результата показывается действие по `relationship`:

  | `relationship` | Действие |
  |---|---|
  | `none` | «Добавить в друзья» |
  | `outgoing_request` | «Заявка отправлена» + «Отозвать» (`request_id`) |
  | `incoming_request` | «Принять» / «Отклонить» (`request_id`) |
  | `friend` | «Удалить из друзей» |

- Ничего не найдено — текст «никого не нашлось», а не ошибка.

## Ключевые правила

- **Статус связи — с сервера.** Клиент не выводит `relationship` из списков друзей и заявок:
  он рисует то, что пришло в `UserSearchResult` (конституция, Статья 8).
- **Встречная заявка не превращается в дружбу.** Ответ `incoming_friend_request_exists` (409)
  показывается как «этот пользователь уже отправил вам заявку» с действием «Принять» — второе
  действие не выполняется скрыто.
- **Удаление из друзей предупреждает о последствии.** Подтверждение говорит, что письма этой
  пары, находящиеся в пути, будут отменены — это правило сервера, клиент его только сообщает.
- **Заявки обновляются при входе на экран, при возврате на вкладку и по кнопке.** Push о новых
  заявках в этой версии нет: клиент узнаёт о них, запрашивая список.
- **Повторная заявка после отказа разрешена** — отдельного состояния «отклонена» не существует,
  пара возвращается в «нет связи».

## Ошибки на экране

| Код | Что видит пользователь |
|---|---|
| `friend_request_exists` | «Заявка уже отправлена» + обновление списков |
| `incoming_friend_request_exists` | «Вам уже отправили заявку» + «Принять» |
| `already_friends` | «Вы уже друзья» + обновление списков |
| `friend_request_not_pending` | «Заявка уже неактуальна» + обновление списков |
| `recipient_not_found` / `user_not_found` | «Пользователь не найден» |
| `validation_error` | «Проверьте имя» под полем поиска |
| `network_error` / `server_error` | «Не удалось загрузить» + «Повторить» |

## Проверки

Тесты на MSW: действия соответствуют каждому `relationship`; поиск не уходит короче 3 символов
и дебаунсится; 409 обновляет списки; удаление из друзей требует подтверждения с текстом об
отмене летящих писем; пустые состояния отличаются от ошибок.
