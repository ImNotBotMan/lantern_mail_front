# Локализация и UI-примитивы

## Responsibility

**Ответственность:** два сквозных слоя, на которых стоят все экраны — тексты на двух языках
и базовые визуальные примитивы с токенами оформления.

## Boundary

- Разрешено: `i18next`, `react-i18next`, `Intl`, CSS.
- Запрещено: знать про письма, друзей и сессии; обращаться к сети; хранить прикладные данные.
  Модуль не решает, что показать, — он даёт кнопку, поле, бейдж, заголовок и текст по ключу.

## Языки

- Русский и английский. Язык по умолчанию — из браузера (`navigator.language`), при отсутствии
  поддержки — `ru`. Выбор пользователя сохраняется в `localStorage` и переживает перезагрузку.
- Переключатель языка доступен с экрана входа (до авторизации) и в шапке приложения.
- Переключение мгновенное, без перезагрузки; текущий адрес сохраняется.

## Ключи и словари

- Словари — `src/shared/i18n/locales/<язык>/<пространство>.json` (`common`, `auth`,
  `letters`, `friends`, `errors`), ключи вложенные, путь вида `область.экран.элемент`
  (`letters.inbox.title`, `errors.not_friends`, `common.actions.retry`). Набор ключей в `ru` и
  `en` совпадает — это проверяет отдельный тест.
- Ни одной строки в разметке: текст берётся только по ключу. Строки не склеиваются конкатенацией —
  порядок слов в английском и русском разный, поэтому подстановки идут через интерполяцию
  i18next.
- Множественное число — через плюральные формы i18next (`letters.inbox.count`), а не через
  условные выражения в коде.
- Даты и время — `Intl.DateTimeFormat` с текущей локалью через `shared/i18n/formatDate.ts`;
  формат дат не собирается руками.

## Ошибки API

- Для каждого кода из `module-backend-contract` есть ключ в пространстве имён `errors`
  (`locales/<язык>/errors.json`, ключи плоские: `invalid_credentials`, `email_taken`).
- Перевод кода — `shared/i18n/apiError.ts` (`errorMessage(error)`): он сам подставляет текущий
  язык и нужное пространство имён экрана не касается.
- Если перевода для кода нет — показывается `message` от сервера: контракт может вырасти
  раньше словарей, и пользователь не должен увидеть технический код.
- Ключ всегда идёт вместе со своим пространством имён (`t('invalid_credentials', { ns: 'errors' })`
  или `t('letters:inbox.title')`): словари не сливаются в `common`, иначе ключ молча
  отрисовывается строкой.
- Отдельный ключ `network_error` — «нет связи», с кнопкой повтора.

## UI-примитивы

Кнопка, ссылка, оформленная кнопкой (`LinkButton`), поле с подписью и текстом ошибки,
многострочное поле (`Textarea`), бейдж статуса, индикатор загрузки, пустое состояние,
состояние ошибки, шапка, layout приложения и отдельный layout для входа.
Модалки в наборе пока нет: подтверждение необратимого действия показывается inline на экране
(так сделано для «выйти на всех»), модалка появится вместе с удалением из друзей.

- Оформление — CSS-переменные (цвета, типографика, отступы) плюс CSS-модули; рантайм-CSS-in-JS
  не используется.
- Цвет — не единственный носитель смысла: статус письма это текст плюс бейдж, а не только
  оттенок.
- Интерактивные элементы доступны с клавиатуры и имеют видимый фокус. Правило для модалки,
  когда она появится: закрытие по `Esc`, фокус переходит внутрь и возвращается обратно.
- Тема одна — светлая. Тёмная тема и настройки вида — не в этой версии. *(Выведено из состава
  первого билда; не подтверждено.)*

## Проверки

Тесты: каждый ключ существует в обоих словарях (проверка равенства наборов ключей в CI);
переключение языка меняет текст без перезагрузки и сохраняется; неизвестный код ошибки
показывает `message` сервера; inline-подтверждение требует второго шага и отменяется без
запроса к серверу.
