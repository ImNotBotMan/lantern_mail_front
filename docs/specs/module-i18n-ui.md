# Локализация и UI-примитивы

## Responsibility

**Ответственность:** два сквозных слоя, на которых стоят все экраны — тексты на двух языках
и базовые визуальные примитивы с токенами оформления.

## Boundary

- Разрешено: `i18next`, `react-i18next`, `Intl`, CSS, Tailwind v4 и компоненты shadcn
  (`src/components/ui`).
- Запрещено: знать про письма, друзей и сессии; обращаться к сети; хранить прикладные данные.
  Модуль не решает, что показать, — он даёт кнопку, поле, бейдж, заголовок и текст по ключу.

## Языки

- Русский и английский. Язык по умолчанию — из браузера (`navigator.language`), при отсутствии
  поддержки — `ru`. Выбор пользователя сохраняется в `localStorage` и переживает перезагрузку.
- Переключатель языка доступен с экрана входа (до авторизации) и в шапке приложения.
- Переключение мгновенное, без перезагрузки; текущий адрес сохраняется.

## Ключи и словари

- Словари — `src/shared/i18n/locales/<язык>/<пространство>.json` (`common`, `auth`,
  `letters`, `chats`, `friends`, `city`, `errors`), ключи вложенные, путь вида `область.экран.элемент`
  (`letters.inbox.title`, `errors.not_friends`, `common.actions.retry`). Набор ключей в `ru` и
  `en` совпадает — это проверяет отдельный тест.
- Ни одной строки в разметке: текст берётся только по ключу. Строки не склеиваются конкатенацией —
  порядок слов в английском и русском разный, поэтому подстановки идут через интерполяцию
  i18next.
- Множественное число — через плюральные формы i18next (`letters.inbox.count`), а не через
  условные выражения в коде. Если за числом стоит неизменяемая единица, склонять нечего:
  отсчёт повторной отправки — `forgot.retryIn` с `{{seconds}}` и «с»/«s» рядом, без
  плюральных ключей (иначе наборы ключей `ru` и `en` разошлись бы по числу форм).
- Даты и время — `Intl.DateTimeFormat` с текущей локалью через `shared/i18n/formatDate.ts`;
  формат дат не собирается руками.

## Ошибки API

- Для каждого кода из `module-backend-contract` есть ключ в пространстве имён `errors`
  (`locales/<язык>/errors.json`, ключи плоские: `invalid_credentials`, `email_taken`).
- Перевод кода — `shared/i18n/apiError.ts` (`errorMessage(error)`): он сам подставляет текущий
  язык и нужное пространство имён экрана не касается.
- Если перевода для кода нет — показывается `message` от сервера: контракт может вырасти
  раньше словарей, и пользователь не должен увидеть технический код.
- Ключ всегда идёт вместе со своим пространством имён (`t('invalid_credentials', { ns: 'errors' })`
  или `t('letters:inbox.title')`): словари не сливаются в `common`, иначе ключ молча
  отрисовывается строкой.
- Отдельный ключ `network_error` — «нет связи», с кнопкой повтора.

## UI-примитивы

Кнопка, ссылка, оформленная кнопкой (`LinkButton`), поле с подписью и текстом ошибки,
многострочное поле (`Textarea`), бейдж статуса, индикатор загрузки, пустое состояние,
состояние ошибки, шапка, layout приложения и отдельный layout для входа.
Диалог (`Dialog`) — единственная модалка набора: оверлей, заголовок, крестик, фокус-трап,
`Esc` и возврат фокуса туда, откуда диалог открыли; во время запроса диалог не закрывается.
Появилась с выбором марки при запечатывании — первым местом, где inline-подтверждения мало,
потому что нужен список выбора. Подтверждения необратимых действий по-прежнему показываются
inline на экране. Нативный `<dialog>` не используется: jsdom не умеет `showModal`, и ловушку
фокуса нельзя было бы покрыть тестом. На узком экране диалог прижат к низу и занимает всю
ширину. *(Выведено из реализации; не подтверждено.)*

- Оформление — CSS-переменные (цвета, типографика, отступы) плюс CSS-модули, с переходом на
  Tailwind (раздел ниже); рантайм-CSS-in-JS не используется.
- Цвет — не единственный носитель смысла: статус письма это текст плюс бейдж, а не только
  оттенок.
- Интерактивные элементы доступны с клавиатуры и имеют видимый фокус. Правило модалки:
  закрытие по `Esc`, фокус переходит внутрь (в элемент с `data-autofocus`, иначе в сам
  диалог), `Tab` ходит по кругу, после закрытия фокус возвращается на кнопку-источник.
- Тема одна — светлая. Тёмная тема и настройки вида — не в этой версии. *(Выведено из состава
  первого билда; не подтверждено.)*

## Стили и переход на Tailwind

В будущем оформление целиком переезжает на Tailwind v4 *(решение пользователя)*. Пока идёт
переход, действуют правила *(выведено из текущей настройки; не подтверждено)*:

- **Сейчас.** Tailwind подключён в `shared/ui/global.css` только слоями `theme` и `utilities`,
  без preflight: сброс Tailwind поменял бы вид всех экранов на CSS-модулях. Стили модулей
  лежат вне слоёв и поэтому сильнее утилит. На Tailwind уже стоят компоненты shadcn
  (`src/components/ui`, первый — Aceternity `3d-card` в выборе марки).
- **Токены — в `@theme`** (`shared/ui/tokens.css`, `@theme static`): цвета, радиусы, шрифты и
  размеры текста одновременно CSS-переменные для модулей (`var(--color-surface)`) и утилиты
  (`bg-surface`, `text-ink-muted`, `rounded-md`, `font-body`, `text-lg`). Палитра Tailwind
  выключена (`--color-*: initial`): `bg-gray-50` не сгенерируется, цвет — только из токенов.
  Компоненты из реестров shadcn при добавлении переводятся на токены.
- **Отступы.** `--space-*` остались переменными для модулей. Шаг сетки Tailwind тоже 4px:
  `space-1…4` = `p-1…p-4`, но `space-5` (24px) = `p-6`, `space-6` (32px) = `p-8`.
- **Новый код** может писаться на утилитах; правка существующего экрана не обязана его
  переводить. В одном элементе не смешивать класс модуля и утилиты на одно и то же свойство:
  модуль победит молча.
- **Порядок классов** выравнивает `prettier-plugin-tailwindcss` (`npm run format`), в том
  числе внутри `cn(...)`.
- **Цель перехода:** экраны и примитивы — с CSS-модулей на утилиты по одному модулю, затем
  включается preflight и базовые стили `global.css` сокращаются до того, чего он не покрывает.
  Последний CSS-модуль удаляется вместе с этим правилом; `--space-*` — вместе с ним.
- Тесты не опираются на классы оформления — только на роли, подписи и текст, поэтому переход
  их не трогает.

## Проверки

Тесты: каждый ключ существует в обоих словарях (проверка равенства наборов ключей в CI);
переключение языка меняет текст без перезагрузки и сохраняется; неизвестный код ошибки
показывает `message` сервера; inline-подтверждение требует второго шага и отменяется без
запроса к серверу.
