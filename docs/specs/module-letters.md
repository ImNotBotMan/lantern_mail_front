# Письма

## Responsibility

**Ответственность:** всё, что пользователь делает с письмом в браузере: список отправленных,
входящие с конвертами, экран письма, редактор черновика, действия жизненного цикла
(запечатать, распечатать, отправить, прочитать, удалить).

## Boundary

- Разрешено: `module-front-api-client` (эндпоинты `/letters/*`), `module-front-session`,
  `module-front-friends` (список друзей для выбора получателя), `module-front-i18n-ui`.
- Запрещено: вычислять статус письма из дат, решать, что получателю видно, обращаться к сети
  напрямую. Статус и форма ответа приходят с сервера.

## Экраны

| Адрес | Что показывает |
|---|---|
| `/sent` | отправленные: черновики, запечатанные, в пути, отменённые; статус, получатель, даты |
| `/inbox` | входящие: конверты в пути и доставленные письма |
| `/letters/:id` | письмо; представление выбирается по полю `view` |
| `/letters/new`, `/letters/:id/edit` | редактор черновика: получатель, текст |

## Ключевые правила

- **Представление — по `view`, а не по догадке.** `sender` — всё; `incoming_preview` — только
  отправитель и обёртка, без текста и времени доставки; `incoming` — текст, `delivered_at`,
  `read_at`. Отсутствующие в форме поля не выдумываются: конверт не показывает ни текста, ни
  времени доставки, его просто нет в ответе.
- **Прочитано — при открытии.** Открытие доставленного письма (`status: "delivered"`) вызывает
  `POST /letters/{id}/read` один раз, и письмо становится `read`. Уже прочитанное письмо запрос
  не повторяет: экран помнит, для какого письма прочтение уже отправлено, а пришедший в ответе
  `read_at` ставит точку в списке дат.
- **Действия доступны по `status`** как подсказка, а не как замена проверке сервера:

  | `status` | Действия в интерфейсе |
  |---|---|
  | `draft` | редактировать, запечатать, удалить |
  | `sealed` | распечатать, отправить, удалить |
  | `in_transit` | только просмотр (отправитель видит письмо целиком) |
  | `delivered` / `read` | читать |
  | `cancelled` | только просмотр отправителем; получателю письма нет (404) |

- **Получатель — друг или сам автор.** В редакторе получатель выбирается из списка взаимных
  друзей и самого пользователя («письмо в будущее»), а не вводится свободным текстом. Запрет
  всё равно проверяет сервер (`not_friends`, 409) — клиент показывает ошибку, если она пришла.
- **Конфликт состояния — не ошибка пользователя.** 409 `invalid_state` / `letter_empty` /
  `recipient_missing` / `not_friends` показывается понятным текстом, а данные письма
  перезапрашиваются: список мог устареть.
- **Пустое письмо нельзя запечатать.** Кнопка «Запечатать» неактивна без получателя и текста;
  серверная проверка при этом остаётся единственной настоящей.
- **Обёртка без каталога.** Каталога печатей, марок и открыток ещё нет: `postcard_id`,
  `seal_id`, `stamp_id` в первом билде не отправляются (запечатывание — пустым телом), письмо
  показывается как простая обёртка. *(Подтверждено пользователем.)*
- **Черновик сохраняется по кнопке «Сохранить».** Автосохранения нет: новое письмо попадает на
  сервер первым сохранением, существующее — обновлением. Уход со страницы с несохранённым
  текстом спрашивает подтверждение: inline на экране, плюс системный вопрос браузера при
  закрытии вкладки. *(Решение пользователя.)*
- **Действия — из одного компонента.** На экране письма доступны все действия по `status`;
  в строке отправленных — только «Отправить» и «Удалить». Кнопок «Редактировать» и
  «Отправить» нет у письма не в том статусе (в пути — никаких действий).
- **Свежесть.** Входящие и отправленные перезапрашиваются при входе на экран, при возврате на
  вкладку и по кнопке «Обновить». Конверт превращается в письмо при следующем ответе сервера —
  реалтайма в этой версии нет.
- **Строка входящих молчит о том, чего нет.** У конверта в ответе нет ни текста, ни времени
  доставки: строка показывает отправителя, статус и «летит к вам». У доставленного — строку
  «когда» с датой доставки, у прочитанного — с датой прочтения.

## Данные и кэш

- Хуки модуля — `features/letters`: `useSentLetters()`, `useInboxLetters()`, `useLetter(id)` и
  мутации `useCreateLetter`, `useUpdateLetter`, `useSealLetter`, `useUnsealLetter`,
  `useSendLetter`, `useReadLetter`, `useDeleteLetter`. Все ключи — под корнем `['letters']`: статус письма виден и в списке, и на
  экране письма, поэтому мутация сбрасывает корень, а не отдельный список.
- Своей копии письма экран не держит: редактор заполняет поля из ответа **один раз на письмо**,
  поэтому перезапрос после сохранения не затирает правки.
- Обновления без оптимизма: после действия данные перезапрашиваются. 409 оставляет письмо на
  экране и показывается текстом.
- **Письма не кэшируются по времени.** У друзей свежесть глобальная (30 секунд), у писем
  `staleTime: 0` и для списков, и для письма: статус меняется сам по часам — конверт становится
  письмом, доставленное прочитанным, — поэтому вход на экран всегда спрашивает сервер.
  *(Выведено из правила «свежесть без реалтайма»; ошибку нашёл e2e: письмо открывалось из кэша
  конвертом уже после доставки.)*

## Ошибки на экранах

| Код | Что видит пользователь |
|---|---|
| `not_friends` | «Получатель не друг» и подсказка отправить заявку |
| `invalid_state` | «Письмо уже изменилось» + обновление данных |
| `letter_empty` / `recipient_missing` | «Нельзя запечатать: нет текста / получателя» |
| `not_found` (404) | «Письма нет» с возвратом к списку |
| `network_error` / `server_error` | «Не удалось загрузить» + кнопка «Повторить», сессия не теряется |

## Проверки

Сделано (MSW): три формы по `view` — письмо отправителя целиком, конверт без текста и без
времени доставки, доставленное письмо; действия по `status` (в пути — никаких); «Отправить» и
«Удалить» требуют подтверждения; 409 `not_friends` показывает перевод кода и оставляет письмо
на месте; отсутствующее письмо объясняет 404 и предлагает списки; ошибка загрузки даёт
«Повторить»; сохранение черновика открывает его же адрес с id; «Запечатать» недоступно без
получателя и текста, а с ними — сохраняет и открывает письмо; уход с несохранённым текстом
спрашивает подтверждение («Остаться» сохраняет введённое, «Уйти без сохранения» переходит).

Сделано (MSW), входящие: конверт без текста и без времени доставки, доставленное и прочитанное
письмо с их датами, пустой список, ошибка загрузки с «Повторить», ссылка из строки на экран
письма; прочтение — ровно один `POST /read` при открытии доставленного, никакого запроса для
уже прочитанного и для конверта.

E2E на живом бэкенде (`e2e/letters.spec.ts`): отправитель пишет другу письмо, запечатывает и
отправляет его через подтверждение; получатель в другом браузере видит конверт без текста, после
доставки — само письмо, и открытие фиксирует прочтение; отправитель видит «Прочитано» в
отправленных. Доставку тест ждёт опросом API до `incoming`, а не паузой, поэтому проходит с
любым `DELIVERY_DELAY_SECONDS` (с 60 по умолчанию — около минуты). Быстрый прогон: backend с
`DELIVERY_DELAY_SECONDS=2`, а фронт и `E2E_API_BASE_URL` направлены на него через
`API_PROXY_TARGET`.

Отложено: «Написать письмо» переедет из отправленных в шапку приложения после MVP — сегодня до
действия можно добраться только через `/sent`. *(Решение пользователя.)*
