# Сессия

## Responsibility

**Ответственность:** пара токенов пользователя и всё, что с ней делают: вход, регистрация,
тихий refresh при загрузке приложения, выход на устройстве и на всех, признание сессии
закрытой, экран аккаунта. Три guard'а: защищённые маршруты, требование города и страницы входа.

## Boundary

- Разрешено: `module-front-api-client` (эндпоинты `/auth/*`, `/users/me`), `localStorage`,
  роутер (guard, переход на вход, адрес возврата после входа).
- Запрещено: экраны писем и друзей, i18n-тексты ошибок (возвращает код ошибки), бизнес-правила
  писем. Модуль не решает, что показать после входа.

## Состав

- **`tokens.ts`** — хранение: access в памяти модуля, refresh в `localStorage` под одним ключом.
  Запись/чтение/очистка пары. Хранилища может не быть (приватный режим) — тогда пара живёт
  до перезагрузки страницы.
- **`sessionStore.ts`** — состояние вне React: `loading` (идёт проверка при загрузке),
  `authenticated`, `anonymous`, текущий пользователь и ошибка проверки; методы `login`,
  `register`, `logout`, `logoutAll`, `updateUser`, `closeSession`. `updateUser` обновляет
  профиль в уже открытой сессии (например, после выбора или смены города), но не открывает
  и не закрывает её. Здесь же мост для `api-client` (access,
  refresh, «сессия закрыта»), который тот получает при создании, — поэтому цикла
  `api-client ↔ session` нет.
- **`useSession.ts`** — доступ экранов к состоянию через `useSyncExternalStore`. Состояние
  живёт вне React, потому что закрыть сессию может `api-client` — вне дерева компонентов.
- **`guard.tsx`** — три guard'а: `RequireAuth` (пока `loading` — заглушка, при `anonymous` —
  переход на `/login` с сохранением исходного адреса), `CityRequired` (без выбранного города —
  на `/city`) и `GuestOnly` (авторизованного уводит со страниц входа на `/inbox`). Тихая
  проверка сессии запускается из `RequireAuth` и `GuestOnly`.
- **`navigation.ts`** — адрес возврата после входа: сохранённый guard'ом, иначе `/inbox`.

## Ключевые правила

- **Bootstrap при загрузке.** Есть refresh-токен → тихий `/auth/refresh`, затем `/users/me`;
  нет или отказ — `anonymous`. Приложение не мигает экраном входа, пока идёт проверка.
  Проверка одна на вкладку: повторный refresh отозвал бы пару, которую только что выдал
  предыдущий, поэтому guard'ы запускают её через модульный флаг.
- **Сеть при bootstrap не разлогинивает.** Отказ пришёл по сети или 5xx — состояние остаётся
  `loading` с ошибкой, экран показывает её с кнопкой «Повторить», пара токенов на месте.
- **Пара меняется только вместе.** Каждый refresh возвращает новую пару, и клиент сохраняет
  её целиком: старый refresh после этого недействителен, а его повторное предъявление сервер
  считает кражей и закрывает всю сессию.
- **Автоматический разлогин — только по отказу сервера** (инвариант 3 архитектуры).
- **Явный выход срабатывает всегда.** Кнопка «Выйти» очищает пару локально сразу и лишь
  затем пытается `/auth/logout`: пользователь, попросивший выйти, не остаётся внутри из-за
  обрыва сети. Цена решения: если запрос не дошёл, refresh-токен живёт на сервере до
  истечения срока и остаётся в списке сессий — локальный выход его не отзывает.
  *(Выведено как следствие UX-ожидания «вышел — значит вышел»; подтверждено пользователем.)*
- **Выход во всех сессиях** — отдельное действие (`/auth/logout-all`) с подтверждением:
  отзывает сессии на всех устройствах, включая мобильные. Порядок обратный явному выходу:
  сначала запрос к серверу (для него нужен access-токен), затем локальная очистка; ошибка
  сервера оставляет сессию открытой и показывается на экране.
- **Одна сессия в браузере, но несколько вкладок.** Вкладки не синхронизируются через
  события хранилища в первом билде: рассинхрон ограничивается тем, что каждый refresh
  обновляет `localStorage`, а неудачный — закрывает сессию в своей вкладке.
- **Возврат на исходный экран.** После входа пользователь попадает туда, куда шёл до
  редиректа на `/login`; без сохранённого адреса — на `/inbox`.
- **Авторизованный на страницах входа.** `/login` и `/register` закрыты `GuestOnly`: тот,
  у кого сессия жива, оказывается на `/inbox` и формы не видит.
- **Продукт требует город.** `CityRequired` стоит между `RequireAuth` и layout'ом продукта:
  пользователь без города попадает на `/city`, откуда выйти можно только выбрав город (или
  выйдя из аккаунта). Сам `/city` лежит вне этого guard'а, внутри `AuthLayout`: это уже не
  вход, но ещё не продукт. Правило зеркалит сервер (письмо без города не отправить), но
  не подменяет его: отказ всё равно придёт от API.
- **Регистрация ведёт на выбор города.** После регистрации `navigate('/city')` напрямую, а
  не по сохранённому адресу: у нового пользователя города нет, и любой экран продукта его
  всё равно вытолкнул бы туда же. Вход по паролю идёт по сохранённому адресу — город у
  существующего пользователя обычно уже есть.

## Пользователь видит

- Экраны `/login` и `/register` — отдельный layout: логотип, переключатель языка (он нужен
  до входа) и форма по центру.
- Форма входа: email, пароль. Форма регистрации: email, `username` (3–32, `[a-z0-9_]`),
  пароль (8–128) — те же ограничения, что проверяет сервер, чтобы не отправлять заведомо
  неверное; ответ сервера всё равно показывается.
- Ошибки входа (`invalid_credentials`) и регистрации (`email_taken`, `username_taken`,
  `validation_error`) — под полем, по коду ошибки: `email_taken` под email, `username_taken`
  под `username`, остальные — над формой.
- Экран `/account` (пункт «Аккаунт» в навигации): `username`, дата создания, город профиля
  с действием «Изменить», «Выйти» и «Выйти на всех устройствах». Пока недельный лимит
  смены не истёк, вместо кнопки — строка «Город можно изменить с <дата>». Подтверждение
  выхода на всех — inline на странице: кнопка заменяется вопросом и парой «Да, выйти на
  всех» / «Отмена».

## Проверки

Тесты на MSW: bootstrap с валидным refresh и без него; отказ refresh → `anonymous`; обрыв
сети при bootstrap → остаётся `loading`/ошибка, но не разлогин; повторный bootstrap не
предъявляет refresh дважды; guard возвращает на исходный адрес; вход и регистрация
показывают коды ошибок под своими полями; «выйти» очищает пару даже при обрыве сети.

E2E на живом бэкенде (Playwright, Chrome; `npm run test:e2e`; бэкенд — на `localhost:8000`):
вход с возвратом на запрошенный адрес, регистрация с выбором города, неверный пароль, выход
с проверкой после перезагрузки, «выйти на всех» с отзывом сессии во втором браузерном
контексте. Пользователи создаются через API с уникальным `username`/email на прогон; город
им ставится тем же API, что и экран выбора (`createUser(..., null)` оставляет без города,
чтобы проверить сам шаг).
